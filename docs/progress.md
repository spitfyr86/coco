# Goal progress and context layout

CoCo derives checkpoints from your session goal, established plan, and saved conversation. You do not need to write milestones. The progress bar remains visible before assessment, with an unknown state rather than an invented percentage. For an existing session without a tracker, click **Load session progress**: one explicit coaching request reconstructs the agreed plan and assesses its current state without capturing a new screen. For new sessions, the first coaching reply derives the plan in the same request. If no agreed plan exists, the coach proposes goal-specific checkpoints; an ambiguous goal prompts clarification. The main view shows a completion bar and numbered status markers; hover a marker to read its title/status. The editor includes a status legend and completion bars for the six most recent assessments. The percentage counts completed milestones equally; in-progress work is not assigned a made-up percentage. Completing the listed plan does not independently prove the overall goal is achieved.

**Automatic progress on Fresh check** is on for newly derived plans and new sessions, and can be disabled per session. Existing plans retain their saved preference. Change it in Session progress. Each explicitly requested Fresh check asks the selected coaching model to assess the plan in the same request as the coaching reply, using the supplied checkpoint and conversation. No timers, extra assessment calls, or requests on edits/toggles. Follow-up messages reuse context without reassessing progress. Assessment instructions/data increase token usage and may increase response time/cost.

Statuses are Not started, In progress, Needs verification, and Complete. AI changes include a reason, supporting evidence when available, and checkpoint number. Expand the assessment under a milestone to inspect it. Missing evidence for a claimed completion is downgraded to Needs verification. AI conclusions remain fallible: source changes alone do not establish that tests passed.

Changing a status manually protects it from AI updates; **Allow AI updates** releases that protection. Editing a milestone title resets that milestone's assessment. Plan controls are disabled while a request is active. Undo last assessment restores unchanged AI statuses while preserving manual corrections. An undone checkpoint stays in history; existing-plan reassessment requires a new Fresh check. Undoing initial plan generation removes unchanged generated checkpoints; Load session progress can reconstruct them again. Unknown/duplicate IDs or malformed model output leave progress unchanged and show a notice; readable coaching guidance is retained when available. Changing the goal or plan while a request runs prevents stale assessments from overwriting changed items. Delayed autosaves cannot overwrite newer AI progress.

Progress, automatic-assessment preference, manual overrides, evidence, and up to 30 assessment snapshots are saved per session and restored after restart. New sessions start empty. Current plans and assessment text may be sent to the selected provider as coaching context; common credential patterns are redacted. Captured screen/repository/reference bodies still require refresh after restart. Plan reconstruction includes bounded early/recent saved conversation (first and last 12 messages, 2,000 characters each); omitted middle turns or truncated messages can miss prior decisions, so inspect the generated checkpoints. There is no provider call simply from opening or switching a tab. Once derived, checkpoints restore immediately on reopening. The model returns a validated JSON envelope for assessment requests; providers that cannot follow it fall back to coaching without changing progress.

Drag the divider at the right edge of the context sidebar to resize it. The preferred width is constrained to 220–480 pixels and the displayed sidebar never exceeds 45% of the app width. A focused divider supports Left/Right in 10-pixel steps and Home/End for its bounds. Double-click resets to 278 pixels. Dragging previews the width; releasing commits it. Pointer cancellation restores the saved width.

The hamburger button beside the conversation title collapses or expands the sidebar. Goal progress stays visible, and New Session and Settings remain accessible in the header while collapsed. Width and collapsed state are saved **per session**. Resizing the window can temporarily cap the visible width; expanding the window restores the preferred width. Layout changes do not capture context or invoke a model.
